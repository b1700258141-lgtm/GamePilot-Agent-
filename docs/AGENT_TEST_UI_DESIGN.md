# Agent 自动测试前端设计与实施（第③项）

状态：2026-10-13，页面与自动测试 API 已接入，等待页面验收。离线流程和网页真实模型单格通路已验证；真实证据见 `docs/validation/AGENT-WEB-REAL-SMOKE-20261013.md`。

## 2026-10-13 skill 方案更新

以下原始设计保留为第③项实施记录；当前页面改为按 skill 驱动，无须手动选择测试目标。默认 skill 在受伤且有药水时喝药，否则攻击；当前场获胜且还有剩余场次时进入下一场，最后一场结束后收尾。独立判定器逐步检查规则。2026-10-14 起，缺陷配置改为可多选列表；不勾选时按 seed 以 70% 正常、30% 随机一种缺陷运行，旧版单缺陷开关仅作为下文历史设计保留。上传入口接受不超过 4,000 字符的 Markdown/纯文本策略，保存于本地专用卷，选择后由真实模型读取；离线替身只演练默认 skill。上传内容不能改变可用工具、游戏规则或预算，也不会作为代码执行。报告保存所选 skill 快照和模型实际输入。当前网页预算最多 50 次动作和 50 次模型调用，每次最多请求 512 输出 Token；此前真实单格证据属于旧规则和预算。

## 目标与边界

在现有 `/ui/` 中加入“手动战斗 / Agent 自动测试”两个入口。手动战斗的创建、
恢复和动作能力继续可用。自动测试每次只运行**一个目标、一个 seed、一个靶场
配置**，Agent 选择动作，服务端执行并由独立规则判定器给结论。用户能看到
每一步真实发生了什么、为什么停止，以及如何用相同参数再跑一次。

本页服务于本地演示。Agent 运行使用独立靶场实例，不更改当前手动会话、
普通游戏 API 的规则或数据库卷；缺陷在一次运行开始时固定，运行中不能切换。
所有页面结论从服务端报告读取，不由浏览器重算游戏规则。

### 配置区

- **测试目标**：满血使用药水、受伤后治疗、击败敌人并验证结束，对应现有
  `full-health`、`healing`、`victory`。用用户能理解的名称，保留目标 ID 于详情。
- **随机种子**：独立数字输入，默认 42；提示可输入的安全整数范围。留空时由
  服务端按手动战斗的规则随机生成 31 位种子，并在运行配置、报告与页面显示
  实际种子；相同种子和动作顺序可重现游戏结果，Agent 仍可能选择不同动作。
  种子输入与缺陷开关分别校验。
- **已知缺陷**：默认关闭（`normal`）；开启后单选“治疗越过生命上限”
  `potion_overheal`、“喝药不消耗药水”`potion_not_consumed`、“死亡后反击”
  `retaliate_after_death`。一次只启用一个 profile。治疗类缺陷推荐 `healing`，
  死亡后反击推荐 `victory`；更改缺陷不偷偷更改目标。不匹配时提示“该目标
  可能到不了缺陷触发条件”，未触发要单独显示，不能写成漏检。
- **执行方式**：默认“离线演练”，明确标注“测试替身，不代表真实模型能力”。
  页面选项显示“deepseek-flash”，同时注明实际请求模型 ID 为
  `deepseek-v4-flash`；只在服务端已配置密钥时可选。提交处显式显示每次最多 6 次模型
  调用、每次最多请求 512 输出 Token、最多 6 次动作，输入 Token 和金额无
  硬上限，费用没有可靠单价时为 unknown。真实运行需要单独勾选付费确认。
  密钥只从服务端环境变量读取，不进入浏览器或响应体。
- 点击“开始自动测试”后锁定本次参数，生成新的运行 ID；刷新页面不得重新提交
  或重复产生付费调用。同一时间只允许当前本地演示实例运行一个自动测试任务。

### 过程区

顶部显示运行阶段和实际计数，不用按时长猜百分比。列表按序展示初始快照、
模型选择、工具参数校验、HTTP 动作结果、状态与新增事件、独立规则检查。
被拒绝的工具请求显示拒绝原因，并明确“未向游戏发出动作”；格式纠正也标记为
模型调用。每步可展开“模型回复原文（若有）”“前后状态”“规则期望/实际”。
模型只发工具调用而没有文字时写“模型未提供文字说明”，不能生成一段貌似
来自模型的决策理由。模型输入全文、环境变量和密钥不放进默认页面。模型回复
和工具结果一律作为纯文本渲染，不能把外部内容当成 HTML 或可执行代码。

运行中使用一个带 `role=status` 的句子播报阶段变化；步骤列表不逐条抢焦点。
按钮与表单字段有可见标签、键盘焦点和至少 44×44 像素点击区；状态同时
使用文字与颜色，错误贴近对应字段。移动端不产生横向滚动，长 ID 和规则
说明可换行。上述反馈、进度与无障碍取自项目现有 UI 和 ui-ux-pro-max 的
长任务反馈、状态文字及对比度规则。

### 结论区

结论同时写清“游戏规则”和“Agent 测试任务”，避免发现缺陷时出现误导性的
绿色“游戏通过”。例如：**“发现游戏缺陷：死亡后反击”**；副文案
“独立规则 `R-NO-RETALIATE-ON-KILL` 失败，Agent 成功检出，游戏规则未通过”。

| 服务端事实 | 页面主结论 | 必须附带的原因 |
| --- | --- | --- |
| 目标覆盖且规则通过 | 游戏规则通过 | 满足的覆盖条件、停止原因、重放结果 |
| 靶场触发且目标规则失败 | 发现游戏缺陷 | 缺陷名、规则 ID、期望/实际、动作序号 |
| 其他规则失败 | 发现规则异常 | 实际失败的规则与事实，不冒充选中缺陷的检出 |
| 缺陷未触发且目标已覆盖 | 未触发缺陷 | 已尝试动作、覆盖条件；不称为漏检 |
| 已触发但 Agent 未发现目标规则 | Agent 漏检 | 触发证据、目标规则及实际停止原因 |
| 目标覆盖不足或预算耗尽 | 目标未完成 | 未满足条件与剩余/耗尽预算；同时注明缺陷是否触发 |
| 模型、游戏、重放或存储出错 | 执行错误 | 出错阶段及安全的错误说明 |

主结论按执行错误、规则失败、Agent 漏检、目标未完成、未触发缺陷、
规则通过的顺序判定；覆盖、触发与重放仍作为独立事实展示，不被主结论隐藏。
“无模型重放一致/不一致/未执行”独立展示；重放出错不能显示为通过。
Token 分输入、输出和合计；供应商未返回用量时写 unknown，不能显示 0。
费用没有可靠计价时同样写 unknown。报告下载由服务端根据运行 ID 提供，
不把本机绝对路径直接放进网页。

## 最小服务端契约（实现时新增）

现有游戏 API 只有创建、读取、执行动作，不能从浏览器选择靶场 profile；
原有 `run_agent` 在结束后才返回完整报告。因此新增薄的一层运行接口，复用
LangGraph Agent、靶场、独立判定与现有报告，不在前端实现规则。

| 接口 | 用途 | 关键字段 |
| --- | --- | --- |
| `POST /api/v1/agent-test-runs` | 校验参数、预算和真实模式确认，创建隔离运行；返回 202 | `goal_id`, 可选 `seed`, `profile`, `provider_mode`, `paid_ack` → `run_id` 与实际 `seed` |
| `GET /api/v1/agent-test-runs/{run_id}` | 恢复页面、轮询状态与已确认步骤 | 包含实际 `seed` 的固定参数、`queued/running/completed/error`、阶段、动作/调用计数、步骤、结论 |
| `GET /api/v1/agent-test-runs/{run_id}/report` | 读取原始 Agent/游戏/重放证据 | 版本号、报告内容或受控下载 |

运行中约每秒轮询一次，小样本最多 6 次动作；页面隐藏后可降低频率。
后端在“工具校验完成”“动作与规则检查完成”等事实确定时发布递增序号的
进度快照，最终仍以 `AgentRunReport` 与 `RunReport` 为准。浏览器刷新后按
运行 ID 恢复，不自动重跑。PostgreSQL 模式保存运行参数、状态和完整报告；
内存模式可演示，但重启后运行列表会丢失，页面必须如实提示。原始 JSON
继续保留在受控报告目录；界面只访问经过校验的运行 ID，不能接受文件路径。

“切换缺陷再测”复制目标、seed、执行方式和预算，重新展示缺陷配置并创建
**新**运行；旧报告不覆盖。两个运行只有 seed、目标、执行方式与预算相同时
才显示并排比较，比较中明确 Agent 动作可能不同。真实模式的每次新运行都
重新确认付费范围，不因上一次确认而自动调用。

## 实施切片与验收

1. 新增单次运行接口和隔离靶场装配；先用离线替身贯通运行、逐步状态、
   最终报告与刷新恢复，验证普通游戏会话不受影响。
2. 在现有静态页加入模式入口、配置表单、过程与结论卡片；保留手动操作测试。
3. 接入真实模型选项与服务端预算守卫，验证未确认、缺密钥、重复提交、
   执行错误均不会误发额外模型请求；核对实际 Token 与费用口径。
4. 覆盖正常、三种已知缺陷、未触发、漏检、目标未完成和错误状态；核查
   小屏、键盘操作、焦点与文字对比度。完成后由所有者在页面验收。

当前实施位于 `src/gamepilot/web/`、`src/gamepilot/api/agent_test_routes.py`、
`src/gamepilot/web_runs.py`。运行报告在 `artifacts/agent-web-runs/` 另存原始
JSON；PostgreSQL 模式还在 `agent_test_runs` 表保存完整记录，内存模式重启后
无法恢复。每个服务进程只允许一个活跃自动测试；本地交付使用单进程。
页面默认离线测试替身，真实模式需服务端密钥和每次单独付费确认。当前仅验证
离线缺陷检出、正常通过及页面对照，真实模式尚未调用，须单独评价其结果。
