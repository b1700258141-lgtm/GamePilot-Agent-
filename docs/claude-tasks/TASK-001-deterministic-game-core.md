## 5. 领域模型

实现一个玩家对战史莱姆的游戏会话。

### 初始值

| 属性 | 数值 |
|---|---:|
| 玩家 HP | 100/100 |
| 玩家药水 | 2 |
| 玩家攻击 | 18～25 |
| 史莱姆 HP | 60/60 |
| 史莱姆攻击 | 20～35（确保失败分支可由公开动作触发） |
| 战斗状态 | `active` |
| 回合数 | 0 |

### 动作规则

#### `attack`

1. 仅在战斗为 `active` 时允许；
2. 使用会话私有的随机数生成器计算玩家伤害；
3. 史莱姆 HP 最低为 0；
4. 如果史莱姆死亡，状态设为 `won`，本回合不反击；
5. 否则使用同一会话的随机数生成器计算史莱姆伤害并反击；
6. 玩家 HP 最低为 0；
7. 如果玩家死亡，状态设为 `lost`；
8. 成功动作后回合数加 1。

#### `use_potion`

1. 仅在战斗为 `active` 时允许；
2. 玩家满血时禁止使用；
3. 药水为 0 时禁止使用；
4. 恢复 25 HP，但不得超过 100；
5. 药水数量减 1；
6. 史莱姆随后正常反击；
7. 如玩家死亡，状态设为 `lost`；
8. 成功动作后回合数加 1。

### 不变量

- HP 始终位于 0 与最大 HP 之间；
- 药水数量不得为负；
- `won` 或 `lost` 后不得继续执行动作；
- 非法动作不得造成任何部分状态修改；
- 每个游戏会话拥有独立的随机状态；
- 相同 seed 与相同合法动作序列必须产生相同的伤害、事件和结果；
- 比较确定性时可以排除 `session_id`，且实现中应避免用不可控时间戳破坏事件可比性。

## 6. 结构化事件

每次合法动作均追加结构化事件。事件模型应稳定、可序列化，并至少表达：

- 回合号；
- 行动方：`player` 或 `slime`；
- 动作类型：攻击、使用药水或受到治疗等；
- 本次伤害或治疗数值；
- 动作完成后的玩家 HP 与史莱姆 HP；
- 必要时记录剩余药水。

可以将一个玩家指令拆成多个事件，例如玩家攻击事件和史莱姆反击事件。不要只记录无法机器处理的日志字符串。

## 8. API 要求

### `GET /health`

返回明确的健康状态，例如：

```json
{"status": "ok"}
```

### `POST /api/v1/game-sessions`

请求：

```json
{"seed": 42}
```

`seed` 可以可选；未提供时由服务生成并在响应中返回，从而仍可回放。

成功返回 HTTP 201 和完整游戏快照。

### `GET /api/v1/game-sessions/{session_id}`

成功返回当前完整快照；不存在时返回 HTTP 404 和稳定的错误结构。

### `POST /api/v1/game-sessions/{session_id}/actions`

请求示例：

```json
{"action": "attack"}
```

或：

```json
{"action": "use_potion"}
```

成功返回更新后的完整快照。领域冲突返回 HTTP 409；Pydantic 请求校验错误保留 FastAPI 的 HTTP 422。

错误响应至少包含可机器识别的错误码和可阅读消息，不要向客户端暴露堆栈信息。

## 9. 测试要求

至少覆盖以下内容：

### 领域单元测试

- 初始状态正确；
- 攻击伤害位于定义范围；
- 史莱姆死亡后不会反击；
- HP 不会低于 0；
- 药水治疗不超过最大 HP；
- 满血和无药水时不能使用药水，且状态不发生部分修改；
- 战斗结束后不能继续动作；
- 相同 seed 和动作序列产生相同事件与最终状态；
- 不同会话的随机状态不会互相污染。

### API 集成测试

- 健康检查；
- 创建会话返回 HTTP 201；
- 查询存在和不存在的会话；
- 执行动作并观察回合与历史变化；
- 无效动作值返回 HTTP 422；
- 领域冲突返回 HTTP 409；
- 错误响应结构稳定。

测试不得依赖真实网络或外部服务，不得因随机性产生偶发失败。
