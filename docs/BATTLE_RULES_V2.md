# 战斗规则 v2

新建战斗默认使用 v2。已有数据库会话标记为 v1，恢复时仍按旧规则重放；不会清理旧存档。API 为兼容旧客户端保留 `slime`、`slime_hp` 字段作为“当前敌人”的数据字段，实际类型由 `enemy_type` 指明。

## 初始状态与敌人

玩家 100/100 生命、3 瓶药水、0 金币。敌人由种子独立抽取：史莱姆 60%（60 HP，反击 12–18）、哥布林 30%（80 HP，反击 18–27）、巨魔 10%（170 HP，反击 35–45）。同一种子和动作顺序始终产生相同敌人、伤害与掉落。玩家攻击伤害为 18–25。

## 喝药与结束

药水效力固定为 25。实际回血为 `min(25, 生命上限 - 当前生命)`，因此 90 HP 喝药实际回血 10，100 HP 喝药实际回血 0；两者都消耗一瓶并触发存活敌人的反击。新版 `potion` 事件的 `value` 记录固定效力 25，`player_hp` 记录截断后的生命值。没有药水、或战斗已经结束时，动作被 409 拒绝且状态不变。

敌人生命归零后不再反击。击杀史莱姆掉落 1–3 金币，击杀哥布林掉落 10–20 金币；金币计入玩家余额并生成 `drop` 事件。巨魔没有配置击杀奖励，正常策略无法击败它。

## 缺陷靶场

- `potion_overheal`：仍消耗药水，但把固定 25 点直接加到当前生命，可能超过 100。
- `potion_not_consumed`：喝药成功而药水数量不减。
- `retaliate_after_death`：敌人死亡后仍反击；玩家死亡后也错误地允许继续行动。默认策略会在终态后尝试一次攻击验证后一种情况。
- `loot_anomaly`：按 `seed % 3` 选择不掉落金币、金币数量越界、掉落其他物品三种可复现变体。

默认 Agent 策略开局满血喝药，之后受伤且有药水时喝药，药水耗尽后攻击至终态，再测试一次终态动作限制。真实模型与离线替身共用同一套公开规则、独立判定器与最多 20 步预算。离线替身测试只证明工程闭环，不能代替真实模型能力结论。
